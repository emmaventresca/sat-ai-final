Four differences that are structural rather than cosmetic:

  1. 182 recognitions, not topics. The bank is classified at the grain of the thing a student actually gets wrong, which is what makes a per-recognition diagnosis possible at all.
  2. A tier above the exam. 1,306 Challenge questions sit beyond what the test asks, and 599 Foundations questions below it. Neither tier exists on the real paper; both were authored because students at each end had nothing to work on.
  3. Every wrong answer is tagged with the error that produces it, so the app can drill a mistake across topics instead of drilling a topic.
  4. A missed question never counts as done. It returns until it is answered correctly, and the Challenge tier will not open until every Hard question in a recognition is right.

Cost-cutting, with evidence

The obvious lever is a cheaper model, and the measurement says it is not the lever. Authoring the same cell on three models:

Haiku is barely cheaper than Sonnet, and only 1.6× cheaper than Opus, because the spend is dominated by cache reads of a large prompt on every call rather than by output tokens — a cost every model pays. The real lever is prompt size, not model choice. That is a counterintuitive result and it is measured rather than assumed.

6. Safety

Three defences, each built before it was needed, each with a real incident.

Overspending — the circuit breaker

tools/cli.py holds a breaker that stops a run after a set number of consecutive failures. Authoring runs are long and unattended; a dead usage window would otherwise burn the whole queue against a wall.

Agent malfunction — an outage is not a verdict

Real incident. A verification run hit the usage limit and recorded status: "error" on 1,251 questions. Since only verified items are served, those 1,251 good questions were silently withheld from students for a reason that was never about them. The fix is that an error now leaves the item untouched: the solve did not happen, so nothing was learned about the question.

Copyright — the originality gate

tools/check_books.py indexes the College Board corpus and rejects any authored item that overlaps it. No third-party question text is ever copied; the source books are used to study how a question is asked.

8. Limits and next steps

Known limits

  • Not deployed. The login is client-side and the bank is static JSON, so any public host serves /data/act/questions.json to anyone with the URL. DEPLOY.md documents the intended fix: Cloudflare Pages behind Cloudflare Access, which gates the whole site rather than the app.
  • Generation is local-only. On-demand authoring runs through the claude CLI on one machine. A deployed student cannot trigger it without a hosted endpoint holding an API key.
  • Local mode. Without Supabase configured, accounts live in one browser and teacher codes are not secure. The app says so on its own sign-in screen.
  • 191 questions are held back having failed verification, and 95 are flagged for review. They are not served, but they were paid for.

Next

  • Finish the remaining variety authoring so every recognition asks in several wordings, not one.
  • Full-length timed practice tests, with the paper and extended-time accommodations students actually sit under.
